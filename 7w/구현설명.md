# 구현 설명

## 전체 흐름

RAG는 LLM이 모르는 문서를 물어볼 때 쓰는 방식이다. 모델을 다시 학습시키지 않고, 질문이 올 때마다 문서에서 관련 있는 부분을 먼저 찾아서 프롬프트에 붙여 준다. 모델은 붙어 온 내용을 보고 답한다.

이 실습은 두 부분으로 나뉜다.

문서를 미리 준비하는 부분은 프로그램을 실행할 때 한 번 한다.

1. PDF를 읽는다.
2. 700자 정도로 잘라서 조각(chunk)을 만든다. 조각끼리 100자씩 겹치게 해서 문장이 경계에서 잘려도 앞뒤 내용이 이어지게 한다.
3. 임베딩 모델이 조각 하나를 숫자 384개짜리 목록(벡터)으로 바꾼다. 뜻이 비슷한 글은 비슷한 숫자가 나온다.
4. 조각과 벡터를 Chroma(벡터 DB)에 저장한다.

질문이 들어올 때마다 하는 부분은 이렇다.

1. 질문도 같은 모델로 벡터로 바꾼다.
2. Chroma에서 질문과 가까운 조각 3개를 찾는다.
3. "아래 문서만 보고 답하고 없으면 확인할 수 없다고 해라"는 지시, 찾은 조각, 질문을 합쳐서 프롬프트를 만든다.
4. gemma3:4b가 답을 쓴다.

벡터 값은 사람이 정하지 않고 임베딩 모델이 만든다. 한국어가 되는 다국어 모델(paraphrase-multilingual-MiniLM-L12-v2)을 썼다. 벡터 DB는 이런 벡터를 저장해 두고 가까운 것을 빨리 찾아 주는 데이터베이스인데, 종류가 여럿 있고 수업에서는 Chroma를 골랐다.

단어가 같은지 보는 키워드 검색과 달리 뜻이 비슷하면 찾는다. 대신 질문과 정답 조각의 표현이 많이 다르면 상위 3개에 못 들어올 수 있다.

## 단계별로 채운 부분

step1은 빈칸이 없다. `ChatOllama`에 `temperature=0`을 줘서 같은 질문에는 같은 답이 나오게 했다. 문서에 있는 내용을 그대로 말해야 하는 RAG에는 무작위성이 없는 편이 맞다.

step2에서는 `RecursiveCharacterTextSplitter`의 `chunk_size`를 700, `chunk_overlap`을 100으로 채웠다. 같은 값이 step3, step4, app에 이미 적혀 있어서 맞췄다. 그다음 `split_documents(documents)`로 페이지 단위 문서를 조각으로 바꾸고, `len(chunks)`로 조각 수를 출력하고, `retriever.invoke(question)`으로 질문과 가까운 조각을 찾는다.

step3에서는 검색 개수 `k`를 3으로 채웠다. 교수님 동작 순서 문서에 관련 조각 3개를 검색한다고 되어 있다. 너무 적으면 정답 조각을 놓치고 너무 많으면 프롬프트가 길어져서 느려지고 관련 없는 내용이 섞인다. 프롬프트에는 `{context}`와 `{question}`을 넣었고, 출처 파일명은 `doc.metadata.get("file_name", "확인 불가")`로 꺼낸다.

step4에서는 조각마다 `pdf_file.name`을 파일명으로 붙이고, 대화 기록을 `reversed(chat_history)`로 뒤에서부터 훑어서 가장 최근 사용자 질문을 찾는다. 끝에서 질문을 `"role": "user"`, `"content": question`으로 기록에 저장한다. LLM은 이전 대화를 기억하지 못해서 기록을 매번 프롬프트에 직접 붙여야 한다.

후속 질문은 검색에서도 문제가 된다. "그럼 제출 기한은?"만 검색하면 무엇의 기한인지 알 수 없다. 그래서 검색어를 "이전 질문 + 현재 질문"으로 만들었다.

app.py에서는 `build_rag()`로 RAG 환경을 만든다. Streamlit은 화면에서 뭔가 할 때마다 스크립트를 처음부터 다시 실행하기 때문에, PDF 읽기와 임베딩이 매번 돌지 않도록 `@st.cache_resource`가 붙은 함수에서 한 번만 만든다. 검색에는 `question`이 아니라 `search_query`를 넣는다. 이전 질문이 합쳐진 문장이어야 후속 질문이 동작한다. 나머지는 조각 본문 `doc.page_content`, 대화 기록 문장 `role`과 `message['content']`, 모델이 돌려준 객체에서 글자만 꺼내는 `response.content`, 저장된 대화를 화면에 다시 그리는 `st.write(message["content"])`다.

## 설정값

| 항목 | 값 |
| --- | --- |
| 조각 크기, 겹침 | 700자, 100자 |
| 검색 개수 | 3 |
| 임베딩 모델 | paraphrase-multilingual-MiniLM-L12-v2 (벡터 384개 숫자) |
| 벡터 DB | Chroma (저장 경로 없음, 실행할 때마다 새로 만듦) |
| LLM | gemma3:4b, temperature 0 |
| 답변 길이 제한 | step4는 100토큰, app은 120토큰 |

## 한계

답변 길이를 step4는 100토큰, app은 120토큰으로 제한해 둬서 긴 답은 중간에 끊긴다.
