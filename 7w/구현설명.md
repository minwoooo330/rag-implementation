# 구현 설명

각 단계에서 채운 빈칸과 그 값을 고른 이유를 적었다.

## RAG가 무엇인가

LLM은 학습한 내용만 알고 있어서 이번 학기 공지 같은 최신 문서는 모른다. RAG는 질문이 들어올 때마다 관련 문서 조각을 먼저 찾고, 그 조각을 프롬프트에 붙여서 LLM이 문서를 보고 답하게 하는 방식이다. 모델을 다시 학습시키지 않아도 새 문서를 반영할 수 있다.

## step1. Ollama 연결

`ChatOllama(model="gemma3:4b", temperature=0)`로 로컬 모델을 부른다. `temperature=0`은 무작위성을 없애서 같은 입력에 같은 답이 나오게 한다. 문서에 있는 사실을 그대로 말해야 하는 RAG에는 이 설정이 맞다.

## step2. 검색

| 빈칸 | 값 | 이유 |
| --- | --- | --- |
| `chunk_size`, `chunk_overlap` | 700, 100 | 700자 단위로 자르고 앞뒤 100자를 겹친다. 조각이 작아야 질문과 맞는 부분만 가져올 수 있고, 겹쳐 두면 경계에서 문장이 잘려도 의미가 이어진다. |
| `split_documents(...)` | `documents` | 페이지 단위로 읽은 문서를 조각 목록으로 바꾼다. |
| `len(chunks)` | 조각 수 출력 | 문서 4페이지가 8조각이 되었다. 자르기가 제대로 됐는지 확인하는 용도다. |
| `retriever.invoke(...)` | `question` | 질문을 벡터로 바꿔 가장 가까운 조각을 찾는다. 단어가 같아서가 아니라 의미가 가까운 조각이 찾아진다. |

## step3. Basic RAG

| 빈칸 | 값 | 이유 |
| --- | --- | --- |
| `"k"` | 3 | 가장 가까운 조각 3개를 가져온다. 너무 적으면 정답 조각을 놓치고, 너무 많으면 프롬프트가 길어지고 관련 없는 내용이 섞인다. |
| 프롬프트의 문서 | `{context}` | 찾은 조각들을 이어 붙인 문자열이다. |
| 프롬프트의 질문 | `{question}` | 사용자 질문이다. |
| `doc.metadata.get(...)` | `"file_name"`, `"확인 불가"` | 출처 파일명을 꺼낸다. 값이 없으면 "확인 불가"를 쓴다. |

프롬프트에 "문서에 없는 내용은 추측하지 말고 확인할 수 없다고 답하라"는 규칙을 넣어서 지어내는 답변을 줄인다.

## step4. 대화형 RAG

| 빈칸 | 값 | 이유 |
| --- | --- | --- |
| `page.metadata["file_name"]` | `pdf_file.name` | 조각마다 출처 파일명을 붙인다. |
| `reversed(...)` | `chat_history` | 대화 기록을 뒤에서부터 훑어서 가장 최근 사용자 질문을 찾는다. |
| `"role"` | `"user"` | 사용자가 한 말임을 기록한다. |
| `"content"` | `question` | 사용자가 한 말을 기록한다. |

LLM은 이전 대화를 기억하지 못한다. 그래서 대화 기록을 매번 프롬프트에 직접 붙인다.

후속 질문은 검색에도 문제가 된다. "그럼 제출 기한은?"만으로 검색하면 무엇의 기한인지 알 수 없다. 그래서 검색어를 "이전 질문 + 현재 질문"으로 만들어서 검색한다.

## app.py. Streamlit

| 빈칸 | 값 | 이유 |
| --- | --- | --- |
| `retriever, llm = ...` | `build_rag()` | Streamlit은 입력이 있을 때마다 스크립트 전체를 다시 실행한다. PDF 읽기와 임베딩을 매번 하지 않도록 `@st.cache_resource`를 붙인 함수로 한 번만 만든다. |
| `retriever.invoke(...)` | `search_query` | 이전 질문이 합쳐진 검색어를 쓴다. `question`을 넣으면 후속 질문 검색이 동작하지 않는다. |
| 문서 본문 | `doc.page_content` | 조각의 본문이다. 파일명은 위에서 따로 꺼냈다. |
| 대화 기록 만들기 | `role`, `message['content']` | 기록을 "사용자: ...", "AI: ..." 문장으로 바꿔 프롬프트에 넣는다. |
| 반환값 | `response.content` | `llm.invoke`는 객체를 돌려주므로 답변 글자만 꺼낸다. |
| 기존 대화 출력 | `message["content"]` | 화면이 다시 그려질 때마다 `session_state`에 저장된 대화를 처음부터 출력한다. |

## 설정값 정리

| 항목 | 값 |
| --- | --- |
| 청크 크기, 겹침 | 700자, 100자 |
| 검색 개수 | 3 |
| 임베딩 모델 | paraphrase-multilingual-MiniLM-L12-v2 (한국어 포함 다국어) |
| 벡터 DB | Chroma (저장 경로 없음, 실행 때마다 새로 생성) |
| LLM | gemma3:4b, temperature 0 |
| 답변 길이 제한 | step4 100토큰, app 120토큰 |

## 한계

- 작은 모델(4B)은 서로 다른 날짜가 섞인 문서를 받으면 엉뚱한 날짜를 고를 때가 있다.
- 답변 길이 제한 때문에 긴 답은 중간에 끊긴다.
- 검색은 의미 유사도만 쓴다. 질문과 정답 조각의 표현이 다르면 상위 3개에 못 들어올 수 있다.
- 구체적인 실행 사례는 [실행및결과.md](실행및결과.md)에 있다.
